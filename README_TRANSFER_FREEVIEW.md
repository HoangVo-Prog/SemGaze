# SemGaze → ScanDiff OSIE / COCO-FreeView transfer evaluation

## Source audit

- Base: `HoangVo-Prog/SemGaze`, `method`, SHA `eeffb2c7d3287684c82cbdacddae1c2e4b8e2607` (22 Oct 2026).
- ScanDiff: `aimagelab/ScanDiff` official dataset tree and loaders.
- FS-PSP scoring frames verified against `cvlab-stonybrook/few-shot-scanpath`:
  - OSIE original fixation frame **800 × 600**, metric frame **512 × 384**.
  - COCO-FreeView original fixation frame **1680 × 1050**, metric frame **512 × 320**.
- Official **FS-PSP CVPR 2025 main Table 1** observer split verified from their reference demo and training launchers:
  - **OSIE:** seen IDs `0..9`, unseen IDs `10..14` (10 seen, 5 unseen).
  - **COCO-FreeView:** seen IDs `3..9`, unseen IDs `0..2` (7 seen, 3 unseen).
  - The code auto-detects whether ScanDiff stores IDs as `0..N-1` or `1..N`; it shifts **all IDs consistently** for one-based encoding and otherwise fails rather than guessing.
- For FS-PSP **Table 1**, use `--scope unseen` (the default). `--scope seen` corresponds to the subject group in the supplementary seen-observer experiment, NOT the main paper's Table 1.
- Inputs are downloaded JPEG/images and fixation JSON, **not** precomputed DINOv2 tensors or ScanDiff cluster labels.
- Only *WHERE* is generated: these files lack SemGaze's WHAT/WHY/HOW training/evaluation annotations.

## Required dataset paths

After ScanDiff's standard download/unzip, point `--scandiff-data` at `ScanDiff/data`:

```
ScanDiff/data/
  osie/
    images/
    processed_fixations/
      osie_fixations_train.json
      osie_fixations_test.json
  coco_freeview/
    images/
    COCOFreeView_fixations_train.json
    COCOFreeView_fixations_test.json
```

The `--osie-root` and `--coco-freeview-root` arguments override the per-dataset paths when archives were extracted separately. The script verifies **the full 15/10 subject populations** against the FS-PSP official IDs, then maps them onto ScanDiff's original `subject` field (0-based or 1-based). Both partitions must have test records and same-observer train supports. Split and mapping are recorded in `transfer_protocol.json`.

## Commands — official FS-PSP main-paper split

Run at the **SemGaze repository root** with the existing train/eval environment and a full checkpoint directory. **Do not pass custom unseen-subject flags.**

```bash
# 1. Preflight: confirm official subject IDs and support coverage without GPU
python evaluate_transfer_freeview.py \
  --checkpoint /path/to/SemGaze/checkpoint_dir \
  --scandiff-data /path/to/ScanDiff/data \
  --dataset both --scope unseen \
  --split-protocol fspsp-main \
  --k-values 1 5 10 --draws 1 --batch-size 1 \
  --output-dir runs/eval_fspsp_unseen \
  --dry-run

# 2. Actual inference-only evaluation (new empty output directory)
python evaluate_transfer_freeview.py \
  --checkpoint /path/to/SemGaze/checkpoint_dir \
  --scandiff-data /path/to/ScanDiff/data \
  --dataset both --scope unseen \
  --split-protocol fspsp-main \
  --k-values 1 5 10 --draws 1 --batch-size 1 \
  --output-dir runs/eval_fspsp_unseen
```

For a separate **seen** experiment, change `--scope seen --output-dir runs/eval_fspsp_seen`. Use `--scope both` to produce both partitions and a pooled `all` summary. **Do not use the `all` scores as Table 1 comparisons; Table 1 reports unseen observers only.**

The support planner uses the FS-PSP `select_fewshot_subject` principle: choose **K distinct training stimulus names shared by all target observers in the partition**, and gather each observer's scanpath for those same stimuli. Supports come only from ScanDiff **train**, and predictions score ScanDiff **test**. Sampling is deterministic using stable SHA-256 seeds. `--draws 10` uses disjoint K-sized image blocks for 10 realizations if at least `K*10` common images exist. The original authors' exact random support samples are **not** reproduced unless their saved per-K sampling files are provided.

For a custom/non-paper partition, explicitly opt out with `--split-protocol manual --osie-unseen-subjects ... --coco-freeview-unseen-subjects ...`. This will **not** be labeled as an FS-PSP Table 1 split.

The main protocol auto-detects the observer ID base; if your ScanDiff JSON has some other identifier convention, the preflight fails and prints the observed values. `--fspsp-subject-id-base 0` or `1` may force **validation** of that exact contiguous ID population, but will never remap an unrelated observer set silently.

## What is produced

- `transfer_protocol.json`: source checkpoint identity, fixed annotation/scoring frames, subject partition, all K/draw support record IDs, validation/capping statistics.
- `predictions.jsonl`: one generated path and GT/metrics per `(dataset, query, K, draw)`.
- `metrics.json`: per-target selected partitions (`unseen` by default), aggregated by K, with per-draw diagnostics. With `--scope both`, `all` is generated by pooling the two target subsets, not by macro averaging them.
- `metrics.md`: ready-to-copy Markdown table with SM, MM, SED for each dataset, target partition, and K.
- `metrics_fspsp_table.md`: side-by-side **OSIE / COCO-FreeView unseen-only** Table-1-style rows for K=1,5,10 (generated with the official partition). This layout does NOT imply full training/data-protocol equivalence.
- `resolved_config.json`: the checkpoint model config used to load the model.

Scoring uses the existing SemGaze audited ScanMatch, MultiMatch and VAME/SED utilities, changing only the OSIE screen size to the proper **512×384**. The full checkpoint weights, tokenizer, `<END_FIX>` convention, greedy WHERE generation, and no-gradient evaluation mode are retained. Requires `multimatch-gaze==0.1.3` and the normal SemGaze `pyproject.toml` environment.

## Interpretation / methodological differences

1. **Matched observer split is not identical model-training protocol.** FS-PSP trains on the target dataset's seen subjects, then tests on its held-out unseen subject group. Your checkpoint was trained on COCO-Search18/AiR, not on the FS-PSP OSIE/COCO-FreeView seen-subject training sets. We adopt their *exact subject partition*, but `seen` remains a target-defined label, not an identity present during source model training. Additionally COCO-Search18 and COCO-FreeView share COCO images, so inspect any source/target image overlap before describing this as image-unseen cross-dataset generalization.
2. **Fixation count is oracle-provided**, matching the current SemGaze WHERE architecture (`Generate ... exactly N fixation points`). The GT *coordinates and durations* of the target query are not put in the input, but its GT *length* is. Document this conditioning alongside results.
3. **Fixation length mismatch**: the source checkpoint supports up to **10 fixations**, while FS-PSP's original setup allows up to **20** for both OSIE and COCO-FreeView. Query/support sequences longer than `--max-fixations 10` are explicitly capped at ten and counts are recorded. The paper's saved support draws and image splits must also be compared before making a strict head-to-head claim. Matching the observer split alone is insufficient.
4. **Time units**: ScanDiff's fixation `T` is milliseconds, as its dataset loaders state. Support WHERE serializations quantize durations to 0–999 ms just like the source model, whereas GT scores use raw milliseconds.
5. **No silent repair**: invalid/out-of-frame GT causes an explicit error; empty scanpaths are skipped with their counts reported; invalid/empty generations contribute deterministic zero SM/MM and GT-length SED by the SemGaze scoring convention.
6. **Full numerical parity** with FS-PSP's table requires matching image train/test membership, actual support draws, 20-fixation length policy and metric edge cases, not only held-out subject IDs. ScanDiff's published image splits were not verified identical to the exact FS-PSP split; this needs to be checked with local data before using Table 1 as a strict paired comparison.

## Tests

```bash
python -m py_compile evaluate_transfer_freeview.py
pytest -q test_transfer_freeview.py
```

These tests exercise JSON shape, image leakage, **FS-PSP official 0-based/1-based observer partition mapping**, shared stimuli for every subject within a draw, fixed K supports across disjoint draws, truncation, aggregation and OSIE metric dimensions with stub scorers. They do not run the 8B checkpoint because the checkpoint and full ScanDiff data live on your GPU server.
